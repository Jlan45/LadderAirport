# DNS / DDNS / ACME Implementation Plan

> Track implementation with the checkboxes below. Each task must leave tests green before the next task begins.

**Goal:** Add provider-backed DNS automation and ACME DNS-01 protocol certificates while keeping certificate private keys on Agent and preserving a working deployment through failures.

**Baseline:** Create `feature/dns-acme` from `v0.9.3` / current `main`.

**Target:** `v0.10.0`

**Spec:** `docs/superpowers/specs/2026-07-27-dns-acme-design.md`

## Delivery rules

- Do not import DDNS-GO as a runtime dependency.
- Do not mix protocol certificates with `panel/internal/pki`.
- Do not store protocol private keys in Panel.
- Do not make DNS/ACME network calls inside SQLite transactions.
- Every external mutation must be idempotent and recoverable after restart.
- Every task must add Chinese operator-facing errors and redaction tests.
- Existing v0.9.3 behavior remains the compatibility baseline.

## Implementation gate

Implementation should not begin until these decisions are accepted:

- Provider set: AliDNS, DNSPod, Cloudflare, Callback.
- Protocol private keys remain Agent-only.
- Managed TLS is bound per node/inbound pair.
- DNS-01 is the only v0.10.0 challenge type.
- Existing self-signed behavior remains as opt-in legacy compatibility.
- Target release is `v0.10.0`.
